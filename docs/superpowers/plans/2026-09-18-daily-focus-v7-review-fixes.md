# 每日聚焦 V7：审核修复（P0 / P1 / P2） Implementation Plan

**Goal:** 让补丁 `docs/V7.patch`（对应 `docs/daily-focus-v7-design.md`）从「能跑但不绿、真实数据下事件通道被例行公告占据」修到：测试全绿、事件通道只收真催化、页面把证据口径说清楚、聚焦股票池能追溯逐日理由。

**背景：** 补丁应用后 `pnpm check` 通过，但 `pnpm test` 有 6 项失败（1 项是补丁自带新测试暴露的真实 BUG，5 项是过时断言）；真实数据复验发现 A 级「核心事件」大量是法律意见书、业绩说明会、担保/融资租赁进展等例行公告。

## P0：真实性修复（先做）

- [x] **新鲜度按自然日计算**：`scoreEventNovelty` 原先用 24 小时制算「几天前」，把「昨天 10:00 → 今天 15:00」（1.2 天）判成 2–3 日前（50 分）。改为按北京时间自然日差：今天重复 20 / 昨日 25 / 2–3 日前 50 / 4 日以上 70；传闻→正式公告仍按 materialUpdate 抬到 75。
- [x] **事件分类收紧**：政策词去掉裸「意见」（正是它把「法律意见书」判成政策事件 80 分）；`业绩` 收窄为 `业绩预告|业绩快报|净利润|…`，不再把「业绩说明会」当成重大业绩变化。
- [x] **例行文件识别与封顶**：新增 `isRoutineFiling()`，命中后归入 `other` 并把重要度封顶 55、持续性封顶 45（低于事件门槛 60）。判定分四层：交易性实词不降级 → 例行强特征（股东会/决议公告/回购注销/限制性股票）优先 → 宽泛催化词（回购/政策/规划/补贴）不降级 → 例行清单（法律意见书/股东大会/业绩说明会/担保进展/募集资金/现金管理/融资租赁/进展公告）。
- [x] **时效项改真实衰减**：原先把设计 §7 的「10% 时效」写死成常量 100，等于给所有事件白送 10 分。改为 `timelinessScore`：≤24h 100 / ≤72h 60 / 更早 30；`buildEventClusters(events, tradeDate)` 接收交易日（不传时退回本批最新时间，保持确定性）。
- [x] 补齐/修正单测，`pnpm test` 恢复全绿（含 5 处过时断言：2 处版本号改从 V7 模块读取、龙头加分改为层级分语义、核心聚焦/观察聚焦文案、分数构成文案）。

## P1：口径与文案

- [x] **证据模式（设计 §33）**：新增 `dailyFocusDataMode` = full / market+authority / market-only，页面新增「证据模式」审计项；非 full 时明确提示——「讨论源覆盖不足：关注度加速信号缺失…」或「文本证据不足：当日无法产生事件通道，榜单主要由市场趋势与热度信号构成」。
- [x] **榜单实测构成**：`dailyFocusLaneNotice` 在「今日没有一只走事件通道」时补一句「榜单全部来自量价趋势与当前热度」，避免把质量模式当成实际构成。
- [x] **分数构成文案统一**：旧记录的 `dailyFocusScoreBreakdown` 不再用 `Math.max(0, …)` 吞掉负调整，并统一为「基础 X ± 调整 Y − 风险 Z = 最终分」。

## P2：评分展示、测试覆盖、池子追溯、字段清理

- [x] **明细区改 V7 双目标**：新增 `dailyFocusV7ScoreRows`，V7 记录显示「研究价值（约两周）/ 当前热度 / 事件得分 / 趋势得分」，**未达门槛的通道显示「未达门槛」**而不是把没计入的分数当成已计入；旧冻结记录仍回落到六维展示。
- [x] **核心事件标注门槛**：明细里区分「核心事件（重要度 X · 新鲜度 Y）」与「当日公告未达事件门槛，仅作证据保留」。
- [x] **热点位不再被放大**：`selectDiversified` 的弹性位与行业放宽只补研究型，热点位固定 2 个（新增 `DAILY_FOCUS_RESEARCH_SEATS` / `DAILY_FOCUS_HOT_SEATS`）。原先补位阶段会继续塞热点股，热点可以占满 8 个名额。
- [x] **热点分支可达**：设计 §22 的 B 级热点分支原先还要求 `finalScore >= 48`，而纯热点股研究分为 0（最终分 ≈ 20），这条路径实际永远走不通。按设计去掉最终分下限，热点数量改由「热点位最多 2」控制。
- [x] **补齐设计 §42 单测**：无事件不能进事件通道、纯强势走趋势通道、热点位最多 2、热度不进入研究分、同行业默认 2（候选不足放宽 3）、sentimentDelta 历史不足为 null、持续确认抵消重复惩罚、过热扣分可超过龙头奖励、同输入必然同输出。
- [x] **聚焦股票池追溯逐日理由（设计 §36）**：池内每只股票新增 `focus`：最近聚焦日的 lane / focusType / 核心事件 + 按日期升序的 timeline + `changed`；界面显示「09-16 事件突破 → 09-17 事件+趋势 · 理由有变化」，产品类型做成名字旁徽标。旧冻结记录留白不猜测。
- [x] **清理悬空字段**：`referenceAudit.leadership.boardCount` 改为真实参考集（只统计当日涨停股）；`lastPrimaryEventClusterId` 落地为 `focusReasonChanged`（与上次聚焦时的核心事件比较），写入快照并在候选行显示「理由有变化」。

## 已知边界

- 例行文件清单是显式规则表，遇到新的例行文案仍可能漏网；调整只需改 `server/eventCluster.ts` 一处，并有 `isRoutineFiling` 单测兜底。
- 「回购注销限制性股票」这类资本事项与「回购公司股份方案」通过 `BROAD_CATALYST` / `ROUTINE_OVERRIDE` 区分，仍属规则判断，不是语义理解。
- 事件通道依赖公告权威源的窗口证明；讨论源覆盖不足时关注度加速信号缺失（页面会写明），但不会因此伪造数值。
