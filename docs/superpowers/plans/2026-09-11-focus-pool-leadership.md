# 聚焦股票池：来源、趋势与「当前时段龙头」 Implementation Plan

**Goal:** 让 5 日聚焦股票池（1）明确只来源于窗口内各交易日的每日聚焦名单；（2）给每只股票一条说清楚的趋势；（3）池内股票能被标注为「当前时段的龙头」，并且每日聚焦的选股本身也把龙头加分算进去。

**Architecture:** 龙头判定需要第三方事实，因此新增两个数据源适配器（东方财富涨停板池、龙虎榜）与一张取证状态表；解析、龙头判定、行情核对都是纯函数（`server/leadership.ts`），入库与历史回填在 `server/leadershipSync.ts`。策略层只消费装配好的 `leadership` 输入并做加分（`daily-focus-v5`），股票池层从数据库逐日读取同一批事实做展示标记，两层共用同一套龙头判定规则。

## 任务 1：涨停板池与龙虎榜适配器（纯函数）

- [x] `server/leadership.ts`：解析涨停池 `getTopicZTPool`（价格按 1/1000 元归一、`fbt/lbt` 归一为 `HH:MM:SS`、连板数、炸板次数、封单资金、行业短名），无 `date` 数据时（非交易日）返回空数组。
- [x] 解析龙虎榜 `RPT_DAILYBILLBOARD_DETAILSNEW` 并按股票聚合：金额取净买额绝对值最大的一条，原因全部保留，避免同一席位明细被重复累加。
- [x] `mergeLeadershipDay`：合并两份数据为「当日龙头事实」，行业名优先用本地已分类口径覆盖接口短名。
- [x] `deriveDailyLeaders`：市场龙头 = 连板 ≥ 2 且进入全市场最高梯队（最高 5 板时取 4–5 板），按「连板数 → 首次封板时间 → 成交额」排序取前三；行业龙头 = 所属行业当日涨停 ≥ 2 家，且是该行业内连板最高的一只。**首板不标龙头。**
- [x] `verifyLimitUpAgainstQuotes`：收盘模式要求价格与涨跌幅全部一致；盘中模式只允许「行情快照取在封板之前」这一种单向时点差，并要求至少六成完全一致。
- [x] 接口只接受交易日参数、返回载荷无法自证日期（`qdate` 是服务器当天日期），因此**任何一批数据都必须与本地同日行情比对通过才可用**。

## 已知边界

- 涨停池接口无法自证数据日期，证明只能来自与本地同日行情的比对。因此**本地行情不是收盘批次的历史日期（例如服务当天没运行到收盘）不会标龙头**：2026-09-10 与 2026-09-03 的本地行情分别停在 10:42 与盘中，核对判定为不可信，这两天的池子成员没有龙头标记，也不加龙头分。
- 盘中核对用的是与涨停池同一批次的行情，仍可能有几秒的时点差；这类差异会被记录为「盘中封板时点差」，收盘后会再抓一次最终涨停池（收盘批次、收盘模式核对）。
- 「龙头」只描述当日可核验的涨停与龙虎榜事实，不含连板高度预测、封板资金强度模型或龙虎榜席位画像，也不是收益承诺。
