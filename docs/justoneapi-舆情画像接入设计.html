一、总览与结论

一句话结论：justoneapi/data-api 不是一个可部署的开源项目，而是商业数据服务 Just One API 的接口目录仓库。 它以统一 REST 接口聚合了 30+ 平台内容，其中跨平台搜索（/api/search/v1）一次调用即可覆盖新闻 / 微博 / 微信 / 知乎 / 抖音 / 小红书 / B站 / 快手——正好是本项目缺失的"全网讨论层"，与已有的股吧、雪球自研抓取形成互补。 接入后配合"名称 / 代码双形态检索"策略，可把讨论覆盖率从股吧单一来源扩展到全网，并在现有评分管线上长出"舆情画像"。

二、仓库分析

2.1 它是什么 / 不是什么

  • 不是开源代码：仓库 72,841 次提交几乎全部是 CI 自动同步 README 接口目录（OpenAPI → README），无可运行的采集代码。
  • 是付费数据服务：令牌、余额、调用量在 dashboard.justoneapi.com 管理；按调用量计费（具体单价需登录控制台确认）。
  • 统一工程约定：所有端点 GET、token 走 query、超时建议 120s、统一业务码（0 成功 / 100 令牌失效 / 301 采集失败 / 302 限流 / 303 超日配额 / 601 余额不足 / 602 令牌限额）。
  • 另有官方 Python SDK（justoneapi-python），本项目服务端为 Node/TS，直接 REST 调用即可。

三、名称 / 代码双形态检索策略（需求点 1）

3.1 现状问题

  • 现有微博抓取（resolveWeibo）只用股票名称做关键词 → 漏掉"600519"形态的讨论；实测中文社媒中代码形态占比不低（截图晒单、行情播报类帖子几乎都带代码）。
  • 股吧按代码板块抓取，天然归属，无此问题；雪球用 $名称$ 语义，也不受影响。
  • 反向风险：裸 6 位数字歧义极大（价格、日期、单号、电话片段），代码命中不等于股票命中，必须消歧。

3.2 查询侧：一次调用、双形态 OR

// 每只股票生成一个跨平台查询表达式（引号 = 精确匹配，防分词误伤）
buildStockQuery(stock) = `"${stock.name}" || ${stock.code}`

// 示例：
贵州茅台  →  "贵州茅台" || 600519
宁德时代  →  "宁德时代" || 300750

// 变体（可选增强，P2 再评估是否启用）：
带市场前缀：SH600519 / 600519.SH   // 仅行情播报类帖子常用
雪球语义：$贵州茅台$                // 跨平台搜索不含雪球，可不加

3.3 归一侧：命中消歧规则（防误配）

命中形态判定规则置信度处理
名称全匹配文本含完整股票名称高直接归属该股
代码 + 语境词代码 ±15 字内出现 股/涨/跌/%/¥/买/卖/仓/盘/停/SH/SZ 等高归属该股
裸代码无语境词，但全文本金融词密度 ≥ 阈值（如 ≥2 个金融词）中归属但降权（情绪权重 ×0.6）
裸代码无语境以上均不满足低丢弃，仅计入噪声统计
多股同帖同时命中多只股票名称/代码—名称优先；每只都计入但分摊权重

五、舆情画像模型

在现有 radarScore 七因子（sentiment / attention / velocity / consensus / sourceQuality / priceConfirm / freshness）基础上，为单股输出六维画像。数据齐备度随平台接入逐步提升，标 ★ 的维度依赖 Just One API 新数据。

维度内容数据来源
① 情绪结构情绪得分、多空占比（pos/neg/mixed/neutral）、分歧度sentiment.ts（现有）
② 热度动能提及量、环比 delta、72h 趋势 sparklineradarEngine（现有）
③ 平台结构 ★sourceMix 扩展到 8+ 平台；跨平台共识度（≥3 平台同向 = 强信号）Just One API + 股吧
④ 传播力 ★互动加权热度（赞/评/转 log 加权）；KOL 浓度（高粉账号占比，字段可得时）Just One API 详情/评论端点
⑤ 话题与事件topics 关键词簇 + 关联新闻/公告事件锚点现有 events + 跨平台 NEWS 源
⑥ 行情联动priceConfirm（现有）；情绪-价格领先/滞后关系（P2 探索）东方财富行情（现有）
